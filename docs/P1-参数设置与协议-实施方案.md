## 一、数据模型与迁移（Flyway）

### 1.1 版本号（待确认）
文档 10.9 写 P1=V25、P2=V26，但仓库现有最高是 `V2__init_dict_data.sql`。
**建议用下一个连续编号 `V3`**（Flyway 按文件名排序，跳跃编号会破坏"顺序即时序"的可读性）。如你坚持用 V25 跳跃编号标识功能模块，告诉我即可。

### 1.2 三张协议表（DDL，字段取自 5.2）
- `sys_agreement`：协议主体（一类型一条）。`code`(PRIVACY/TERMS)、`name`、`scope`(PLATFORM/TENANT)、`status`、`current_version_id`。
- `sys_agreement_version`：**只增不改**。`agreement_id`、`version`(v1/v2)、`content`(Markdown 快照)、`change_summary`、`effective_at`、`need_reconsent`(bool)、`published_by`、`created_at`。
- `sys_agreement_consent`：**只增不删**。`user_id`、`agreement_id`、`version_id`、`action`(AGREE/WITHDRAW)、`channel`(LOGIN/SETTINGS)、`ip`、`user_agent`、`created_at`。

**关键设计点**：存 `version_id` 不存 `version` 字符串——文案快照必须能在三年后原样复现（合规审计要的是"他当时同意的到底是哪段文字"）。

### 1.3 种子
- `sys_agreement` 种两条：`TERMS`（用户协议）、`PRIVACY`（隐私政策），各挂一条 `v1` 占位版本（`content` 为占位 Markdown，上线前由运营替换）。
- `sys_config` 补充结构化 key（参数设置表单用）：`system_name` / `logo_url` / `icp_no` / `support_contact` / `login_notice` / `notify_global_switch`（可用 `ext` JSON 存结构化）。
- 菜单权限种子：**系统管理**下新增「参数设置」菜单（`route_path=/system/param-setting`，`component=system/param-setting`，`perm_code=config:manage`）；协议管理不做独立菜单，内嵌参数设置页的 Tab。

## 二、后端实现

### 2.1 协议模块
- **entity**：`Agreement` / `AgreementVersion` / `AgreementConsent`（MyBatis-Plus，对齐现有 `AuditedEntity` 风格）。
- **service `AgreementService`**：
  - `getActiveVersion(code)` → 当前生效版本（登录页"告知"用，公开）。
  - `listPending(userId)` → 当前用户未同意、或 `need_reconsent=true` 且未对该版本重同意的协议（前端弹层用）。
  - `submitConsent(userId, agreementId, versionId, channel, ip, ua)` → 写 `action=AGREE` 记录（只增）。
  - `withdraw(userId, agreementId, versionId, ip, ua)` → 写 `action=WITHDRAW` 记录（**不删旧**）。
  - `publishVersion(...)` → 管理员新建版本（`need_reconsent` 可选、生效时间可选）。
- **controller `AgreementController`**：
  - `GET /agreements/active`（公开，登录页告知，不需同意记录）
  - `GET /agreements/pending`（登录态，弹层）
  - `POST /agreements/{id}/consent`（同意，必须记录 ip/ua）
  - `POST /agreements/{id}/withdraw`（撤回）
  - 协议管理 CRUD（管理员，`@RequirePerm("config:manage")` 或单独 `agreement:manage`）
- **权限**：读协议/提交同意 = 登录即可；发布版本/管理 = `@RequirePerm`。

### 2.2 参数设置接口
- 扩展或新建 `ConfigController`：
  - `GET /config/group` → 按 `config_type` 分组返回结构化数据，供表单渲染（**不暴露裸 key**）。
  - `PUT /config` → 更新，`@RequirePerm("config:manage")`。
  - 关于我们数据复用同一组 config key，不另建表。

## 三、前端实现（若依动态路由：加菜单行 + 建 vue，路由表不动）

### 3.1 参数设置页 `views/system/param-setting.vue`（需 sys_menu 加菜单行）
四 Tab：
- **基本信息**：结构化表单（系统名称/Logo/备案号/技术支持/登录公告/通知开关），按语义分组渲染，**不暴露裸 key**。
- **用户协议** / **隐私政策**：展示当前生效版本（Markdown 渲染）+ 管理员可发布新版本（Markdown 编辑器 + 变更摘要 + `need_reconsent` 勾选 + 生效时间）。
- **关于我们**：只读展示（数据从 config 读）。

### 3.2 关于我们弹窗
- `AppHeader.vue` 个人中心下拉加「关于我们」项，与「个人中心」「退出登录」同级。
- 点击弹 `el-dialog`：系统名称/版本号/备案号/技术支持/开源组件声明，全从 `sys_config` 读。

### 3.3 协议强制确认弹层（⚠️ 关键约束，见 10.7）
**不要塞 `router.beforeEach`**（那段已有"动态路由同步后必须带原目标重导航"的复杂逻辑，且有过 `name=Forbidden` 的历史坑）。
**正确位置：`AdminLayout.vue` 的 `onMounted` 发一次 `GET /agreements/pending`**，有未同意就弹层（左侧 `change_summary`/首读摘要，右侧全文 Markdown），「同意并继续」/「不同意，退出登录」；弹层期间 `v-if` 遮内容区。首登（无记录）与升级（`need_reconsent=true`）统一走此弹层，文案区分。

### 3.4 个人中心「隐私与协议」Tab
- `profile/index.vue` 现有「基本资料/修改密码」两 Tab → 加第三 Tab「隐私与协议」。
- 列已同意协议 + 时间 + 版本 + 撤回按钮（二次确认 + 说明撤回影响）。撤回调 `POST /agreements/{id}/withdraw`。
